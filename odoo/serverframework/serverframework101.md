# Server framework 101

https://www.odoo.com/documentation/17.0/developer/tutorials/server_framework_101.html

Odoo використовує багаторівневу архітектуру (multitier architecture), що означає розділення представлення, бізнес-логіки та зберігання даних. Точніше, використовується трирівнева архітектура (three-tier architecture).

![](https://www.odoo.com/documentation/17.0/_images/three_tier.svg)

Рівень представлення (presentation tier) є поєднанням HTML5, JavaScript і CSS. Рівень логіки (logic tier) повністю реалізований мовою Python, тоді як рівень даних (data tier) підтримує лише PostgreSQL як систему керування реляційними базами даних (RDBMS).

Залежно від задач вашого модуля, розробка в Odoo може виконуватися на будь-якому з цих рівнів. Тому перед тим як рухатися далі, варто освіжити знання, якщо ви не маєте принаймні середнього рівня підготовки у цих темах.

Щоб пройти цей навчальний матеріал, вам знадобляться базові знання HTML та середній рівень володіння Python. Для складніших тем знадобляться глибші знання в інших областях. Існує багато безкоштовних навчальних матеріалів, тому складно рекомендувати якийсь конкретний ресурс, оскільки все залежить від вашого попереднього досвіду.

Для довідки можна використати офіційний навчальний посібник Python.

Примітка. Починаючи з версії 15.0, Odoo активно переходить на власний фреймворк OWL, який використовується у рівні представлення. Попередній JavaScript-фреймворк ще підтримується, але з часом буде виведений з використання. Це питання розглядатиметься детальніше у складніших темах.

## Модулі Odoo

Як серверні, так і клієнтські розширення в Odoo пакуються у вигляді модулів, які за потреби завантажуються у базу даних. Модуль є набором функцій і даних, що реалізують одну конкретну задачу.

Модулі Odoo можуть або додавати нову бізнес-логіку до системи Odoo, або змінювати та розширювати вже наявну. Наприклад, один модуль може додавати правила бухгалтерського обліку для певної країни до загальної бухгалтерської системи Odoo, тоді як інший модуль може реалізувати підтримку візуалізації у реальному часі для парку автобусів. Усе в Odoo починається і закінчується модулями.

Термінологія: розробники групують бізнес-функціональність у модулі Odoo. Основні модулі, орієнтовані на користувача, позначаються та відображаються як **Apps**, але більшість модулів не є Apps. Модулі також можуть називатися **addons**, а каталоги, у яких сервер Odoo їх шукає, утворюють шлях `addons_path`.

### Склад модуля

Модуль Odoo може містити кілька елементів.

**Бізнес-об’єкти ([Business objects](https://www.odoo.com/documentation/17.0/developer/reference/backend/orm.html#reference-orm)).** Бізнес-об’єкт (наприклад, рахунок-фактура) означується як клас Python. Поля, означені в цих класах, автоматично відображаються на стовпці бази даних завдяки рівню ORM.

**Представлення об’єктів ([Object views](https://www.odoo.com/documentation/17.0/developer/reference/user_interface/view_architectures.html)).** Означують відображення інтерфейсу користувача.

**Файли даних ([Data files](https://www.odoo.com/documentation/17.0/developer/reference/backend/data.html#reference-data))** - XML або CSV файли, що означують дані моделі:

- представлення або звіти
- конфігураційні дані (параметри модулів, правила безпеки)
- демонстраційні дані
- інші дані

**Веб-контролери ([Web controllers](https://www.odoo.com/documentation/17.0/developer/reference/backend/http.html#reference-controllers))** - Обробляють запити від веб-браузерів.

**Статичні веб-дані** - Зображення, CSS або JavaScript файли, що використовуються веб-інтерфейсом або вебсайтом.

Жоден із цих елементів не є обов’язковим. Деякі модулі можуть містити лише файли даних (наприклад, конфігурацію бухгалтерського обліку для певної країни), тоді як інші можуть містити тільки бізнес-об’єкти. У межах цього навчального матеріалу ми створюватимемо бізнес-об’єкти, представлення об’єктів і файли даних.

### Структура модуля

Кожен модуль є каталогом усередині каталогу модулів. Каталоги модулів означуються за допомогою параметра `--addons-path`.

Модуль Odoo означується через його `manifest`.

Якщо модуль Odoo містить бізнес-об’єкти (тобто файли Python), вони організовуються як пакет Python із файлом `__init__.py`. Цей файл містить інструкції імпорту для різних Python-файлів у модулі. Нижче наведено спрощену структуру каталогу модуля:

```
module
├── models
│   ├── *.py
│   └── __init__.py
├── data
│   └── *.xml
├── __init__.py
└── __manifest__.py
```

## Редакції Odoo

Odoo доступний у двох версіях: Odoo Enterprise (ліцензована, із частково закритими джерелами) та Odoo Community (відкрите програмне забезпечення).

Окрім сервісів, таких як підтримка або оновлення, версія Enterprise надає додаткову функціональність для Odoo. З технічної точки зору ці можливості реалізовані як нові модулі, встановлені поверх модулів, що входять до версії Community.
